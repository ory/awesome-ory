# Secure an ASP.NET Core application using Ory Network

This repo demonstrates how you can use self-hosted Ory Kratos with ASP.NET
Core apps. Ory Network support is incomplete and tracked in
[TODO.md](../TODO.md). This app is not for production use and serves as an example of
integration.

## Overview

Base on the template generated by the `dotnet new mvc` command.

## Run locally with Docker

From `dotnet-ory-network`, run:

```bash
docker compose --profile ui up --build
```

Open http://127.0.0.1:5286. The `ui` profile starts the login and registration
UI on http://127.0.0.1:4455. After signing in, return to the app and open
**Identity Info**.

The app uses two Ory addresses:

- `ORY_BASEPATH`: the SDK address, `http://kratos:4433` inside Compose.
- `ORY_BROWSER_URL`: the browser-facing Kratos API, `http://127.0.0.1:4433`.
  Login and signup redirect the browser here to initialise the flow and set
  its CSRF cookie.

Use `127.0.0.1` consistently so the app and Kratos share the session cookie.
The app image requires a separate Kratos service; it does not start an Ory tunnel.

## Develop with the .NET SDK

Install the .NET 10 SDK and Docker. From `dotnet-ory-network`, run:

```bash
docker compose --profile ui up -d kratos kratos-selfservice-ui-node mailpit
export ORY_BASEPATH=http://127.0.0.1:4433
export ORY_BROWSER_URL=http://127.0.0.1:4433
dotnet run --project src/ExampleApp --urls http://127.0.0.1:5286
```

Open http://127.0.0.1:5286 for testing.

### Run tests

```bash
make test
```

This brings the stack up, asserts the behaviour this example demonstrates, and
tears it down again. It needs no credentials and no browser: the test mints a
real Ory session with `curl` and replays it against the app. It also verifies
that login and signup redirect to the browser-facing API.
